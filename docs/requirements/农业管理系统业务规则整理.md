# 农业管理系统业务规则整理

---

## 一、角色职责说明

- **系统管理员**：维护并发布版本化的公司级标准模板，模板中包含幼树和成年树轨道；不参与具体农场年度计划的制定和任务下发。
- **农场管理员**：选择标准模板或复制本农场上一年度计划，创建年度管理计划草稿。
- **农场管理员**：保存计划版本。保存只形成农场年度计划快照，不产生地块任务。
- **农场管理员**：点击"下发任务"，使已保存计划成为当前生效基线，并按阶段向农户下发任务。
- **农场管理员**：通过变更单或临时任务处理当前阶段的现场变化，不直接覆盖已生效基线。
- **农场管理员**：修改未来阶段后保存为新版本，确认下发后更新尚未执行的任务。
- **农户**：执行已下发任务并提交执行记录。执行记录原则上不可覆盖，填写错误时追加更正记录。
- **农场管理员**：记录采收和清园完成时间。这些时间只进入生产档案，不触发计划创建、年度切换或权限变化。

## 二、八大业务问题与建议

### 1. 生产周期如何确定

**建议：保留默认周期（如"上年12月1日至当年11月30日"），允许农场管理员调整，不与采收或清园时间自动联动。**

奉节脐橙果实成熟期为11月下旬至次年1月，生产管理围绕"采果—休眠—萌芽—开花—坐果—成熟—采果"的物候循环展开。以12月为起点符合实际业务。但不同地块因海拔、品种（早中熟vs晚熟）差异，起止日期可能不同，因此应允许管理员按需调整。采收和清园时间不应自动触发周期变更，否则会造成计划混乱。

**结论：默认"12月1日至11月30日"，允许地块级调整。**

### 2. 下一年度计划如何创建

**建议：由农场管理员手动点击"创建下一年度管理计划"，然后选择来源——复制上一年度计划 或 采用标准模板。**

农业管理软件中普遍支持将上一季的版本向前延续，实现逐年对比；同时也可从公共或内部模板开始创建自己的修订版。农场管理员需要根据当年实际情况（如树龄变化、上年经验教训）判断选择哪种来源，不应全自动。

**结论：手动创建 + 选择来源（复制上年 / 标准模板）。**

### 3. "下发任务"的范围

**建议：按阶段滚动下发，全年计划只作为框架展示。**

年度计划确定全年框架后，具体任务应在每个阶段开始前滚动下发。这既考虑了物候动态调整的需要，也符合农业生产的实际情况——从战略计划到战术执行的逐层细化。一次性下发全年任务会导致大量无效或过期任务，增加管理负担。

**结论：年度计划 = 框架，阶段任务 = 滚动下发。**

### 4. 阶段什么时候锁定

**建议：两者结合——管理员确认实际开始时间后锁定该阶段；系统对超期未确认进行提醒。**

阶段锁定不应仅靠日期自动触发（物候可能提前或推迟），也不应完全依赖人工确认（可能遗忘）。正确做法是：管理员在田间观测到物候到达后，在系统中确认"本阶段开始"，系统随即锁定该阶段计划。若超过计划日期一定天数仍未确认，系统发出提醒。

**结论：管理员确认开始后锁定 + 超期提醒。**

### 5. 第一次下发时当前阶段如何处理

**建议：如果已进入第一阶段，点击下发后立即锁定第一阶段；如果到年中才首次下发，过去阶段标记为"未下发"，不允许生成逾期任务，但允许补录实际执行记录。**

这是实际业务中常见的"计划下发晚了"场景。已过去的阶段如果实际已执行，应允许补录执行记录作为生产档案；如果未执行，标记为"未下发"并记录原因。不应自动生成逾期任务或强制要求补做，因为物候窗口已过，补做没有意义。关键在于**保证生产档案的完整性**，而非追究"逾期"。

**结论：当前阶段立即锁定；过去阶段标记"未下发"+ 允许补录，不生成逾期任务。**

### 6. 未来阶段修改后的任务处理

**建议：不能直接修改已下发任务。流程为：保存新计划版本 → 展示差异 → 管理员确认重新下发 → 原未执行任务标记为"已替代" → 生成新任务。**

GLOBALG.A.P等质量标准要求所有文档修改必须记录版本和变更描述。农业管理软件也支持"锁定区域，通过版本历史跟踪更新"。直接修改已下发任务会丢失变更追溯，不符合质量追溯要求。

**结论：版本化变更，原任务标记"已替代"，不删除。**

### 7. 当前阶段允许怎样调整

**建议：保留两个入口——变更单和临时任务，功能不同，不可合并。**

| 入口 | 用途 | 适用场景 |
|------|------|----------|
| **变更单** | 调整原计划中已有任务的日期、用量、执行要求 | 天气变化需调整喷药时间、施肥量微调 |
| **临时任务** | 增加原计划中没有的新工作 | 突发病虫害需额外防治、unexpected 农事 |

两者业务含义不同：变更单是"计划调整"，临时任务是"计划外新增"。合并会导致管理混乱，也难以追溯"原计划是什么、额外增加了什么"。

**结论：保留两个入口，功能分离。**

### 8. 采收和清园是否为同一条记录

**建议：拆成"采收完成时间"和"清园完成时间"两条独立记录，两者都不触发计划逻辑。**

实际业务中，采收（11月下旬至次年1月）和清园（12月至次年1月）时间窗口有重叠但不完全一致。早中熟品种采后立即清园，晚熟品种可能春季采果后才清园。合并在一条记录中无法准确反映实际业务。两者都是重要的生产档案节点，应分别记录，但不应用作计划周期的自动触发器。

**结论：拆分为两条独立记录，仅作档案，不触发逻辑。**

## 三、需要收紧的地方

### 1. 地块级调整不是独立生产周期

农场仍共用一份年度管理计划和默认周期。地块只能设置日期偏移量，例如 +3天、-5天，不能各自建立完全不同的生产年度，否则阶段锁定和任务下发会变得过于复杂。

### 2. "确认阶段开始"和"下发任务"需要明确关系

建议每个阶段采用：

> 调整阶段计划 → 填写实际开始日期 → 确认阶段开始并锁定 → 下发该阶段任务

第一阶段首次下发时，如果尚未确认实际开始日期，系统要求农场管理员一并确认。阶段一旦确认开始，基线内容即锁定。

### 3. "滚动下发"和"未来任务替换"并不总会同时发生

如果严格按阶段滚动下发，未来阶段尚未生成任务，修改后只需要保存新计划版本，不存在替换任务。

"旧任务标记为已替代"只用于两种情况：

- 农场管理员提前下发了未来阶段。
- 当前阶段通过变更单调整了已有任务。
