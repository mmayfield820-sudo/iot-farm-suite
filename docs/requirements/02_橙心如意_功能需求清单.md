## 一、课题定义与项目约束

本节是本项目需求解释和验收的共同依据。后续用户故事如与本节冲突，以本节为准。

### 1.1 项目背景

“橙心如意”服务于重庆市奉节县脐橙产区农业公司旗下橙园。平台围绕“公司标准模板、橙园年度生产计划、地块任务执行、物联网监测与灌溉、生产档案”建立管理闭环。

同一橙园在一个生产年度内使用同一套年度计划和果园轨道，地块只允许设置计划日期偏移量，不单独建立品种、生产年度或模板版本。农场管理员负责年度计划和阶段任务，农户负责现场执行、完成记录和计划外农事补记。

当前项目的生产年度固定为上年 12 月 1 日至当年 11 月 30 日。例如“2027 生产年度”是指 2026-12-01 至 2027-11-30。

### 1.3 角色职责边界

| 角色 | 本项目职责 | 不允许的操作 |
| --- | --- | --- |
| 系统管理员 | 维护橙园、地块、员工账号、角色授权和公司级标准模板；查看全局告警与审计日志。 | 不替代农场管理员处理某橙园的年度计划、阶段启动和任务下发。 |
| 农场管理员 | 在授权橙园内维护果园基础信息和年度计划；确认阶段开始并滚动下发任务；创建变更单、临时任务和历史补录；登记采收/清园节点；登记、绑定和管理设备。 | 不维护公司级标准模板，不修改员工角色或跨橙园授权，不直接覆盖已完成记录。 |
| 农户 | 查看授权地块、计划和监测数据；完成已下发任务；追加完成更正；补记已完成的计划外农事；确认并执行灌溉。 | 不修改模板、果园基础信息、年度版本或阶段规则；不直接调整计划任务日期和要求。 |

原清单中“农户调整本人未完成任务日期、备注和状态”的描述与当前项目业务规则和后端权限不一致，现统一调整为：计划任务变更由农场管理员通过变更单处理，农户只负责执行、完成、更正和计划外农事补记。

### 1.4 账号与授权规则

1. 账号由系统管理员单个创建或通过 Excel 批量导入，不提供公开注册。
2. 员工以唯一工号登录；新账号初始密码为身份证号后六位。
3. 首次验证初始密码后，系统只签发短时资料设置令牌；员工设置不同的正式密码并补充联系方式后，账号才从 `pending_activation` 转为 `active`。
4. 身份证号明文不入库，仅保存基于 `PII_HASH_SECRET` 的 HMAC 摘要和脱敏展示值。
5. 一个账号可具有多个角色；切换角色时前端发送 `X-Active-Role`，后端再次校验角色归属。
6. 农场管理员只能访问授权橙园，农户只能访问授权地块及其设备、任务、遥测和告警。
7. 同一地块同一时刻只能分配给一名农户；同一橙园可授权多名农场管理员。

### 1.5 周期、模板与计划规则

1. 标准模板已发布版本只读，新修改必须发布为新版本。
2. 当前项目提供按品种、省、市筛选模板的接口和人工选择页面；“奉节脐橙优先、通用脐橙其次、通用柑橘再次”的自动排序尚未实现。
3. 果园按实际定植日期自动判断轨道：第 1～3 个生产年度使用幼树轨道，第 4 个生产年度起使用结果树轨道；延长幼树轨道必须填写原因。
4. 年度计划保存为橙园级版本快照，不会立刻生成全年地块任务。
5. 管理员确认阶段实际开始时间后锁定该阶段，再按阶段为有效地块下发任务。
6. 已过去且未下发的阶段不生成逾期任务，但允许农场管理员补录历史执行记录。
7. 重新下发当前阶段时，新计划替代原活动计划，历史计划与已执行记录保留。
8. 当前活动阶段的现场变化使用“变更单”或“临时任务”，不得直接覆盖年度计划基线。
9. 农户完成记录采用追加式留痕；填写错误时追加更正记录，不覆盖或删除原完成记录。
10. 采收完成和清园完成是两条独立档案节点，只用于追溯，不自动触发年度切换或计划生成。

## 二、项目定位与业务闭环

橙心如意是奉节脐橙种植企业的内部生产管理与物联网辅助平台，不面向消费者，也不允许员工自行注册。平台帮助系统管理员维护主数据，帮助农场管理员制定和下发年度农事安排，帮助农户执行任务、处置灌溉并形成可追溯档案。

当前项目闭环为：

```text
系统管理员建立橙园/地块、账号和标准模板
→ 员工首次登录并激活账号
→ 农场管理员安排或确认定植资料，保存年度生产计划
→ 农场管理员确认阶段开始并按阶段下发地块任务
→ 农户执行任务、提交完成记录或补记计划外农事
→ 设备上报温湿度与状态，系统生成告警、天气提醒和灌溉建议
→ 农户二次确认后下发灌溉，设备 ACK 回写结果
→ 农场管理员查看生产档案并登记采收、清园节点
```

## 五、非功能与接口约束

| 编号 | 类别 | 要求 | 当前状态 |
| --- | --- | --- | --- |
| NF-01 | 权限 | 除健康检查、登录和首次设置外，所有业务 API 必须校验 JWT；资源查询和写入同时校验当前角色及农场/地块范围。 | 已实现 |
| NF-02 | 时间 | 数据库存储 UTC；MQTT 使用 Unix 毫秒；API 返回带 `Z` 的 ISO 8601；前端按 `Asia/Shanghai` 展示。 | 已实现，新增接口仍需回归 |
| NF-03 | 标识 | API 使用 `U/F/P/D/MT` 等业务编号；MQTT 只使用 `device_uuid`，不得使用数据库主键或设备展示编号代替。 | 已实现 |
| NF-04 | 幂等 | MQTT QoS 1 重投不得重复写遥测；控制 ACK 必须按 `cmdSeq` 精确关联命令；重复业务提交应返回稳定冲突。 | MQTT 已实现，HTTP 幂等需逐接口完善 |
| NF-05 | 审计 | 关键写操作与审计记录尽量在同一数据库事务中完成；完成记录和计划变更不得物理覆盖历史。 | 已实现主要流程 |
| NF-06 | 可用性 | AI、天气等外部依赖不可用时，不得阻断账号、任务、监测和设备管理等核心功能，并返回可识别的降级状态。 | 已实现基础降级，需端到端演练 |
| NF-07 | 安全 | 生产环境必须更换 JWT/PII 密钥、数据库默认密码，为 EMQX 配置认证、ACL 和 TLS，不得提交 `.env` 或真实个人信息。 | 本地配置具备；生产加固待部署实施 |
| NF-08 | 契约 | REST 以 `contracts/openapi.yaml` 为协作基线，MQTT 以 `contracts/mqtt-topics.md` 为准；变更应先更新契约再同步代码。 | 部分实现；OpenAPI 尚未覆盖全部新增接口 |
| NF-09 | 实时性 | 当前页面通过 API 刷新和命令轮询工作；`contracts/websocket-events.md` 中的实时 WebSocket 尚未实现，不作为本期已交付能力。 | 待实现 |
| NF-10 | 测试 | 核心规则应有单元测试；账号权限、数据库、MQTT 遥测和控制 ACK 应有自动化端到端测试。 | 单元测试已覆盖部分规则；集成测试待补 |

## 六、当前交付结论与待办

### 6.1 当前可验收主流程

1. 系统管理员维护橙园、地块、员工授权和脐橙模板；
2. 员工使用工号与初始密码完成首次激活；
3. 农场管理员设置定植/果园信息并保存年度计划；
4. 农场管理员确认阶段开始、下发任务并进行变更单或临时任务处理；
5. 农户查看计划、完成任务、追加更正和补记计划外农事；
6. 模拟/真实设备完成遥测、心跳、灌溉命令和 ACK 闭环；
7. 系统展示墒情、天气、灌溉建议、普通告警和天气影响提醒；
8. 农场管理员按年度查看生产档案并记录采收/清园节点；
9. 农户使用带授权地块上下文的 AI 农事助手。
