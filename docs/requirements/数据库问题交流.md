# 数据库问题交流

本文记录权限模型和数据库设计中的讨论结论，便于后续实现和评审时查阅。

## 1. 农场管理员的权限如何下放到地块？

### 问题

如果张三是农场 1 的管理员，他是否拥有农场 1 内所有地块的访问权限？这种权限如何实现下放？

### 结论

不需要把农场管理员逐条写入每个地块的 `user_plot_role`。推荐采用权限继承（权限下放）规则：

```text
张三 —— FARM_ADMIN —— 农场 1
农场 1 —— 包含 —— 地块 101、102、103
```

当张三访问地块 101 时，后端可以按以下顺序判断：

1. 检查张三是否是地块 101 的直接授权用户。
   - 是：检查该用户在地块上的角色是否拥有当前权限。
2. 如果不是直接授权用户，查询地块 101 所属的农场：
   - `plot.farm_id = 1`
3. 检查张三是否在农场 1 拥有 `FARM_ADMIN` 角色。
   - 是：检查 `FARM_ADMIN` 是否拥有当前操作权限。
4. 如果角色拥有该权限，则允许访问。

### 需要明确可下放的权限

农场管理员拥有的权限不一定都能作用于下属地块。可以在业务规则中明确哪些权限允许从农场级下放到地块或设备级：

| 权限 | 是否可作用于下属地块/设备 | 说明 |
| --- | --- | --- |
| `PLOT_VIEW` | 可以 |  |
| `DEVICE_VIEW` | 可以 |  |
| `DEVICE_MANAGE` | 可以 |  |
| `ALERT_VIEW` | 可以 |  |
| `IRRIGATION_CONTROL` | 按业务决定 | 需要结合控制风险评估 |
| `THRESHOLD_UPDATE` | 按业务决定 | 需要结合配置权限范围 |
| `FARM_MANAGE` | 不需要 | 这是农场级权限 |

如果希望在数据库中配置该规则，可以为 `role_permission_rel` 增加字段：

```text
allow_descendant_access
```

字段取值示例：

| 值 | 含义 |
| --- | --- |
| `1` | 该权限可从农场作用到下属地块或设备 |
| `0` | 该权限仅限当前农场对象 |

课程项目中，也可以先将这条规则写入权限设计说明和后端判断逻辑，不一定要立即增加数据库字段。

## 2. 用户同时拥有农场角色和地块角色时，关系表如何区分？

### 问题

角色-权限表中记录了“张三-农场管理员”。如果张三同时也是地块 1 的农户，将“张三-农场管理员-地块 1”写入 `user_plot_role`，可能会造成角色范围歧义。

### 结论

通过表的职责约定区分角色作用范围，不在地块关系表中重复记录农场级角色：

| 关系表 | 记录内容 | 作用范围 |
| --- | --- | --- |
| `user_role_rel` | 用户与全局角色的关系 | 全局 |
| `user_farm_role` | 用户与农场角色的关系 | 指定农场 |
| `user_plot_role` | 用户与地块角色的关系 | 指定地块 |

因此：

- 张三是农场 1 的管理员，记录在 `user_farm_role`。
- 张三是地块 1 的农户，记录在 `user_plot_role`。
- 不把农场管理员角色复制到 `user_plot_role`。

## 3. 地块是否需要内部唯一 ID？

### 结论

需要。`plot_id` 作为 `plot` 表的主键，用于在系统内部唯一标识地块。

## 4. 角色和权限是一对一还是多对多？

### 结论

角色与权限是多对多关系：

- 一个角色可以拥有多个权限。
- 一个权限可以分配给多个角色。
- 通常通过中间表 `role_permission_rel` 保存关联关系。

## 5. 用户-农场和用户-地块关系改为多对一的话，原来的关系表需要删除吗？

### 结论

不需要。保留，只需把user_farm_role中的farm_id 设置为PK/FK ；
user_plot_role中的plot_id设置为 PK/FK ；
