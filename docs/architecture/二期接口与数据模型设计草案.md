# 橙心如意二期接口与数据模型设计草案

> 状态：待评审。本文件用于确认二期边界和接口语义；评审通过后，将对应内容写入 `contracts/openapi.yaml`、`contracts/data-dictionary.md` 和 `contracts/error-codes.md`，再开始前后端实现。

## 1. 设计结论

一期的 JWT 鉴权、用户授权范围、设备绑定、遥测、天气代理、灌溉控制和灌溉执行记录继续复用。二期不更换业务 ID，橙园仍使用 `Fxxx`、地块仍使用 `Pxxx`、设备仍使用 `Dxxx`；为兼容既有接口和数据库，REST 路径继续使用 `farms` 表示橙园。

二期新增的业务闭环为：

`基础档案与预置账号 -> 账号激活 -> 种植档案 -> 模板匹配 -> 计划和任务 -> 监测/天气 -> 灌溉建议或今日天气提醒 -> 农户确认灌溉执行 -> 农事、灌溉与审计记录`

服务端必须是权限的最终裁决者。前端隐藏按钮只是交互限制，不能替代地块、橙园和角色校验。

## 2. 已确定的兼容策略

| 一期能力 | 二期处理 | 说明 |
| --- | --- | --- |
| `farm`、`plot`、`device` 及业务 ID | 扩展并复用 | 不迁移 ID；`farm` 在界面显示为“橙园”。 |
| `farmer_plot_scope`、`farm_admin_scope` | 继续作为授权依据 | 一个农户可负责多个地块，但一个地块仅有一个农户负责人；一个农场管理员可管理多个橙园，橙园可配置多名管理员。旧负责人字段仅保留作历史兼容。 |
| 公开注册与注册审批 | 下线 | 不再暴露 `/auth/register`、`/registration-resources`、`/registration-applications/*`；以预置账号激活替代。 |
| `/plots/{plotId}/metrics` | 原样复用 | 作为阶段化土壤湿度卡片和趋势图的数据源。 |
| `/api/weather/forecast` | 原样复用 | 继续以 `plotId` 校验权限，返回未来天气和降雨信息。 |
| 设备绑定与灌溉命令 | 原样复用并补充关联字段 | 建议确认后仍调用设备命令服务，保留 `irrigation_record` 的设备 ACK 结果。 |
| 既有阈值配置、告警 | 保留 | 今日农事提醒使用独立只读资源，仅表达天气对当日任务的影响，避免与设备或监测告警混淆。 |

## 3. 通用约定

- API 根路径仍为 `/api`，时间使用带 `Z` 的 ISO 8601 UTC 字符串，展示时由前端转换为 `Asia/Shanghai`。
- 新增列表接口统一使用 `page`（从 1 开始）、`pageSize`（默认 20、最大 100）及响应 `{ "items": [], "page": 1, "pageSize": 20, "total": 0 }`。已有一期列表接口不强制改造。
- 写操作的响应返回创建或更新后的资源；删除基础档案改为“停用”，不提供物理删除接口。
- 所有会产生业务记录的 `POST` 请求支持 `Idempotency-Key` 请求头，重试时返回首次结果，尤其适用于计划生成、导入确认、任务完成和灌溉建议确认。
- 响应错误沿用现有 `{ code, message, requestId }` 结构。新增业务错误码见第 8 节。
- 写操作均写入操作日志，日志字段包含操作者、动作、资源类型、资源 ID、结果、变更前后摘要、请求 ID 与发生时间。

## 5. 资源与接口草案

### 5.1 账号、基础档案和授权

| 方法和路径 | 权限 | 用途 | 核心请求字段 |
| --- | --- | --- | --- |
| `POST /auth/activation/verify` | 预置员工 | 校验工号或手机号及激活凭证，返回一次性 `activationToken`、只读角色和授权范围 | `employeeNoOrPhone`, `activationCode` |
| `POST /auth/activation/complete` | 持有激活令牌 | 设置用户名、密码并确认联系方式；激活令牌单次、15 分钟有效 | `activationToken`, `username`, `password`, `phone`, `email` |
| `GET /users` | 系统管理员 | 分页查询账号，支持 `keyword`、`role`、`status` | 查询参数 |
| `POST /users/import-jobs` | 系统管理员 | 上传 Excel 并进行预校验，返回导入作业和行错误 | `multipart/form-data`，字段 `file` |
| `GET /users/import-jobs/{jobId}` | 系统管理员 | 查看预校验结果和失败行 | - |
| `POST /users/import-jobs/{jobId}/commit` | 系统管理员 | 确认导入全部有效行；重复确认幂等 | - |
| `GET /users/import-template` | 系统管理员 | 下载 Excel 模板 | - |
| `POST /users` | 系统管理员 | 新建单个预置账号 | `employeeNo`, `name`, `phone`, `email`, `roleCodes`, `farmIds`, `plotIds` |
| `PATCH /users/{userId}` | 系统管理员 | 更新账号信息、角色或范围；范围变更立即生效 | 同上，可选字段 |
| `POST /users/{userId}/activation-code/reset` | 系统管理员 | 重置激活凭证，返回仅可展示一次的明文凭证 | - |
| `PATCH /users/{userId}/status` | 系统管理员 | 启用或停用账号 | `status: active | disabled` |
| `GET /farms` | 已登录 | 查询当前用户可见橙园 | `status` |
| `POST /farms` | 系统管理员 | 新建橙园档案 | `name`, `province`, `city`, `address`, `areaMu`, `managerName`, `note` |
| `GET/PATCH /farms/{farmId}` | 可见/系统管理员 | 查询或更新橙园档案 | `status` 仅可设为 `active`、`inactive` |
| `GET /plots` | 已登录 | 查询当前用户可见地块，农户即“我的地块” | `farmId`, `status`, `keyword` |
| `POST /plots` | 系统管理员 | 新建地块档案 | `farmId`, `code`, `name`, `areaMu`, `location`, `irrigationMethod`, `status` |
| `GET/PATCH /plots/{plotId}` | 可见/系统管理员 | 查询或更新地块档案 | 同上 |
| `GET /plots/{plotId}/devices` | 有地块查看权 | 查询关联设备 | - |

账号激活成功前 `users.user_status` 为 `pending_activation`，不能登录；激活完成后才转为 `active`。账号不能通过任何公开注册接口创建。

### 5.2 品种模板、种植档案与计划

| 方法和路径 | 权限 | 用途 | 核心请求字段 |
| --- | --- | --- | --- |
| `GET /crop-templates` | 已登录 | 查询可匹配的标准模板；农场端可查询全部已发布版本 | `crop`, `province`, `city`, `includeAllVersions` |
| `POST /crop-templates` | 系统管理员 | 创建模板及首个版本 | `name`, `crop`, `province`, `city`, `versionDefinition` |
| `GET /crop-templates/{templateId}` | 已登录 | 查询模板、版本和阶段规则 | - |
| `POST /crop-templates/{templateId}/drafts` | 农场管理员 | 随时以当前农场计划或标准模板创建下一年度管理计划草稿 | `farmId`, `changeNote` |
| `PUT /crop-template-drafts/{draftId}` | 农场管理员 | 修改本农场尚未正式保存的年度管理计划草稿 | `versionDefinition`, `changeNote` |
| `POST /crop-template-drafts/{draftId}/publish` | 农场管理员 | 将草稿保存为本农场下一年度管理计划独立快照 | `productionYear`, `extendYoungTrack`, `trackOverrideReason` |
| `PATCH /crop-templates/{templateId}/status` | 系统管理员 | 启用或停用模板 | `status` |
| `GET /plots/{plotId}/planting` | 有地块查看权 | 查询当前种植档案及匹配模板 | - |
| `PUT /plots/{plotId}/planting` | 有地块管理权 | 登记或更新种植信息 | `templateId`, `plantingDate`, `treeAgeYears`, `soilType`, `note` |
| `GET /plots/{plotId}/growth-stage` | 有地块查看权 | 返回推荐阶段、当前有效阶段、目标土壤湿度范围和计算依据 | - |
| `POST /plots/{plotId}/growth-stage-overrides` | 有地块管理权 | 手动修正当前阶段，保留原因和历史 | `stageCode`, `reason` |
| `POST /farms/{farmId}/plans` | 农场管理员 | 按已保存的年度管理计划向全部已分配负责人的有效地块下发任务；再次下发时需明确替换活动计划 | `regenerate: boolean` |
| `GET /plots/{plotId}/plans` | 有地块查看权 | 查询计划列表 | `status` |
| `GET /plans/{planId}` | 有计划查看权 | 计划详情、模板版本、阶段、任务和调整记录 | - |

模板匹配规则固定为：`脐橙 + 重庆市奉节县`，再到通用脐橙，最后为通用柑橘。系统将匹配到的 `templateVersionId` 写入种植档案和计划，之后的模板变更不会改变既有计划。

标准模板由系统管理员维护，至少提供幼树版和成年树版。农场管理员只读选择标准模板作为基线，但可修改复制到本农场年度管理计划中的阶段、任务、频次和土壤湿度目标。保存后的农场计划是独立快照，标准模板后续发布新版本只增加可选项，不改写任何已保存农场计划。下一年度管理计划可提前维护，不设置由采收清园时间控制的维护窗口。

保存管理计划与下发任务是两个独立动作。页面有未保存修改时不得下发；再次下发后旧计划标记为 `superseded`，并保留全部任务与执行记录。任务模板可通过 `repeatDays` 与 `repeatUntilStageEnd` 定义阶段内周期作业；生成完整计划和地块任务快照时，从阶段内参考日起按间隔展开，且不越过阶段结束日期。采收清园完成时间仅作为生产档案保存，既不计算下一年度开始日期，也不触发或限制计划维护与任务下发。

### 5.3 农事、监测、灌溉建议与提醒

| 方法和路径 | 权限 | 用途 | 核心请求字段 |
| --- | --- | --- | --- |
| `GET /tasks` | 已登录 | 今日、逾期、未来 7 天或月度日历任务 | `scope=today|overdue|next7days|month`, `plotId`, `status`, `month` |
| `GET /tasks/{taskId}` | 有任务查看权 | 查询任务和完成记录 | - |
| `PATCH /tasks/{taskId}` | 所辖橙园农场管理员 | 调整尚未完成任务的计划日期、备注或待办状态；农户无此权限 | `scheduledDate`, `note`, `status` |
| `POST /tasks/{taskId}/completions` | 获授权地块农户 | 记录计划任务完成；灌溉任务可关联一期记录 | `result`, `executedAt`, `executorName`, `note`, `irrigationRecordId?` |
| `POST /plots/{plotId}/ad-hoc-tasks` | 有地块管理权 | 新增计划外巡园、修剪、施肥等记录 | `taskType`, `title`, `executedAt`, `executorName`, `note` |
| `GET /plots/{plotId}/stage-moisture` | 有地块查看权 | 当前湿度、阶段目标区间、阈值状态和更新时间 | - |
| `GET /plots/{plotId}/metrics` | 有地块查看权 | 复用一期趋势数据 | `type`, `from`, `to` |
| `GET /weather/forecast` | 有地块查看权 | 复用一期天气代理 | `plotId` |
| `GET /plots/{plotId}/irrigation-recommendations/current` | 有地块查看权 | 计算或获取有效灌溉建议 | - |
| `POST /irrigation-recommendations/{recommendationId}/confirm` | 有地块管理权且为农户 | 二次确认后下发一期灌溉命令 | `confirmedDurationMinutes` |
| `GET /plan-adjustment-reminders` | 已登录 | 查询当前上海自然日内、可能影响今日任务的只读天气提醒 | `plotId` |
| `GET /plots/{plotId}/management-timeline` | 有地块查看权 | 时间线：计划、完成、灌溉、提醒、湿度摘要 | `from`, `to`, `types` |
| `GET /farms/{farmId}/management-statistics` | 有橙园查看权 | 管理员总览：异常、完成率、最近灌溉 | `from`, `to` |
| `GET /tasks/completion-summary` | 有橙园查看权 | 按地块汇总待完成、已完成和逾期数量 | `farmId` |

灌溉建议只产生建议，不会自动控制设备。建议响应至少包含 `decision`、`suggestedDurationMinutes`、`reasons`、`soilMoisture`、`targetRange`、`weatherSummary`、`deviceId` 和 `expiresAt`。`confirm` 成功后返回一期 `Command`，前端仍须通过命令查询或实时事件展示最终的设备执行结果。

今日农事提醒覆盖连续降雨、高降雨概率、高温、低温霜冻和大风。仅在对应天气确实影响今日未完成任务时生成；提醒无需确认或处置，系统不保留往日提醒。湿度异常和设备离线继续进入既有告警链路。

## 7. 数据模型和状态值

### 7.1 对一期表的扩展

| 表 | 新增或调整字段 | 约束 |
| --- | --- | --- |
| `users` | `employee_no`, `activation_status`, `activation_code_hash`, `activation_expires_at`, `activated_at` | 工号全局唯一；激活凭证仅存哈希；状态为 `pending_activation`、`active`、`disabled`。 |
| `farm` | `province`, `area_mu`, `manager_name`, `note`, `farm_status` | 允许停用，不物理删除。 |
| `plot` | `plot_code`, `area_mu`, `irrigation_method`, `plot_status` | `plot_code` 全平台唯一；仅 `active` 地块可生成新计划和绑定设备。 |
| `farmer_plot_scope` | 无字段变化 | 增加 `UNIQUE(plot_id)`，使一个地块在授权表中最多出现一次；一个农户仍可拥有多个地块授权。 |
| `device` | 无结构性变化 | 绑定关系仍为 `device.plot_id`；设备只能绑定到操作者可管理的橙园内地块。 |
| `irrigation_record` | `recommendation_id`（可空） | 二期确认建议产生的命令回链至建议；手动灌溉保持为空。 |

### 7.2 二期新增表

| 表 | 关键字段 | 目的 |
| --- | --- | --- |
| `crop_template` | `template_id`, `template_name`, `crop_name`, `province`, `city`, `status` | 品种模板的稳定身份和适用地区。 |
| `crop_template_version` | `template_version_id`, `template_id`, `version_no`, `status`, `change_note`, `published_at` | `draft` 可在维护窗口内编辑；`published` 为历史快照，不直接改写；`archived` 仅供追溯。 |
| `growth_stage_template` | `stage_template_id`, `template_version_id`, `stage_code`, `stage_name`, `sort_order`, `duration_days`, `moisture_min`, `moisture_max` | 版本内的生长阶段和土壤湿度目标。 |
| `management_task_template` | `task_template_id`, `stage_template_id`, `task_type`, `title`, `offset_days`, `suggested_time`, `note` | 按阶段生成任务的规则。 |
| `planting_profile` | `plot_id`, `template_version_id`, `planting_date`, `tree_age_years`, `soil_type`, `note` | 每个地块的当前种植档案。 |
| `growth_stage_override` | `override_id`, `plot_id`, `stage_code`, `reason`, `effective_at`, `operator_id` | 手动阶段修正的历史。 |
| `management_plan` | `plan_id`, `plot_id`, `template_version_id`, `status`, `generated_at`, `generated_by`, `superseded_by` | 一次计划生成的不可变依据。 |
| `management_task` | `task_id`, `plan_id`（可空）, `plot_id`, `task_type`, `source`, `scheduled_date`, `status`, `note` | 计划任务或计划外农事。 |
| `task_completion` | `completion_id`, `task_id`, `result`, `executed_at`, `executor_name`, `note`, `irrigation_record_id` | 一次任务完成记录。 |
| `irrigation_recommendation` | `recommendation_id`, `plot_id`, `stage_code`, `decision`, `duration_minutes`, `reason_json`, `status`, `expires_at`, `confirmed_by` | 可解释、可失效、可追溯的规则建议。 |
| `plan_adjustment_reminder` | `reminder_id`, `plot_id`, `reason_type`, `affected_task_json`, `status`, `disposition`, `note`, `handled_by` | 对计划是否仍适用的人工处置闭环。 |
| `audit_log` | `log_id`, `actor_id`, `action`, `resource_type`, `resource_id`, `before_json`, `after_json`, `request_id`, `created_at` | 关键操作追溯。 |

状态值：计划为 `active`、`superseded`、`completed`；任务为 `pending`、`in_progress`、`completed`、`overdue`、`cancelled`；建议为 `pending_confirmation`、`confirmed`、`expired`、`dismissed`；提醒为 `pending`、`handled`。

## 8. 需要加入契约的错误码

| 错误码 | HTTP | 场景 |
| --- | ---: | --- |
| `ACTIVATION_INVALID` | 400 | 工号/手机号、激活凭证或激活令牌无效。 |
| `ACTIVATION_EXPIRED` | 410 | 激活凭证或激活令牌已过期。 |
| `EMPLOYEE_NO_EXISTS` | 409 | 工号重复。 |
| `PLOT_CODE_EXISTS` | 409 | 地块编号重复。 |
| `TEMPLATE_NOT_FOUND` | 404 | 没有可用的匹配模板。 |
| `PLANTING_PROFILE_REQUIRED` | 409 | 未登记种植档案即请求阶段、计划或建议。 |
| `PLAN_EXISTS` | 409 | 已存在进行中计划且未明确 `regenerate`。 |
| `TASK_NOT_ADJUSTABLE` | 409 | 尝试修改模板规则或已完成任务的受限字段。 |
| `RECOMMENDATION_EXPIRED` | 409 | 确认已失效的灌溉建议。 |
| `IRRIGATION_CONFIRMATION_REQUIRED` | 409 | 试图跳过二次确认下发灌溉。 |
| `IMPORT_VALIDATION_FAILED` | 422 | 导入作业存在错误行。 |

## 9. 评审后实施顺序

1. 将确认过的路径、请求/响应 schema 和错误码写入 `contracts/`，并补充上述三个实时事件。
2. 先执行数据库迁移：基础档案、预置账号与激活、模板版本、种植档案和计划任务表；迁移脚本只做新增或可逆字段扩展，不删除一期数据。
3. 按单人开发的纵向切片实现：每一批先完成后端接口和接口测试，再完成对应前端页面，最后立即联调验收。推荐顺序为“档案与预置账号 -> 模板/种植/计划 -> 任务 -> 建议/提醒 -> 导入、统计、审计”。
4. 每个切片都覆盖角色和范围校验，再进入下一批，避免最后集中处理权限问题。
5. 验收以下闭环：预置账号激活、农户越权访问拦截、模板下一周期改版不影响旧计划、灌溉二次确认及设备 ACK、今日天气提醒生成与跨日清理。
