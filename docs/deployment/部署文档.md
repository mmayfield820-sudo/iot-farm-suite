# 智慧农业平台 · 部署与使用文档

> 版本：全栈版（deploy/fullstack）
> 本文档有两种使用方式，选一种即可：
>
> - **方式 A**：在本地电脑上用「一键启动包」把整套平台跑起来
> - **方式 B**：不装任何东西，浏览器直接访问团队已部署的在线环境

---

## 一、怎么选

| 方式           | 适合                                  |
| ------------ | ----------------------------------- |
| **A　一键启动包** | 用户想在"自己电脑上"跑一套完整的本地环境            |
| **B　在线访问**   | 用户只是"想用"这个平台                    |

## 二、系统架构图

```
                    ┌─────────────────────────────── 电脑 ───────────────────────────────┐
  浏览器             │                                                                       │
  用户访问 ────────► │  前端 Nginx :80        ──/api──►  后端 FastAPI :8080                 │
  (老师/用户)         │   (Vue 构建产物)                    │  ▲            │               │
                     │                                      ▼  │            │  AI_SERVICE_URL│
                     │                             MySQL 8.0 (3306)         ▼               │
                     │                             EMQX MQTT :1883  ◄─   AI 服务 RAG :8001  │
                     └───────────────────────────────▲─────────│───────────────────────────┘
                                                     │         │
                                     真板子 BearPi (现场) / 模拟器 (电脑软件)    调 DeepSeek API (云端/外网)
                                     = P001 / P002 地块数据
```

| 服务         | 端口   | 作用                        |
| ---------- | ---- | ------------------------- |
| 前端 Nginx   | 80   | 网页（浏览器访问入口）               |
| 后端 FastAPI | 8080 | 业务 / 鉴权 / MQTT / 转发AI（仅容器内） |
| AI 服务      | 8001 | 农业知识问答（RAG，仅容器内）          |
| MySQL      | 3306 | 数据存储（仅容器内）                |
| EMQX       | 1883 | MQTT 消息中转（板子 / 模拟器连接）     |

> 平台自带演示数据（数据库预置），不接板子 / 模拟器也能登录看到完整页面。
> 板子或模拟器接上后，实时温湿度数据会覆盖演示数据，二者不冲突。

## 三、方式 A：Windows 一键启动

### A1. 环境要求

- Windows 10 / 11（64 位）
- 已安装 **Docker Desktop**（若未安装见 A2）

### A2. 下载Docker

1. 下载并安装 Docker Desktop：

   ```
   https://www.docker.com/products/docker-desktop/
   ```

   一路下一步安装。装完双击打开 Docker Desktop，等右下角图标变绿、显示
   **"Engine running"**。首次启动会提示接受协议，点同意。

   > 若安装时报"虚拟化未启用"，先到 BIOS 打开 Intel VT-x/AMD-V。

### A3. 解压并启动

1. 把「预构建镜像包」解压到一个目录（路径不带中文最稳，比如 `D:\farm`）。

2. **双击「启动.bat」**，等它自动完成 5 件事：

   ```
   ① 检查 Docker        （没装/没开会在窗口里提示，按提示装好再试）
   ② 生成配置文件        （首次自动生成，登录密钥已自动随机生成）
   ③ 加载平台镜像        （首次约 3~5 分钟，之后跳过）
   ④ 启动全部服务        （MySQL / EMQX / 后端 / AI / 网页）
   ⑤ 自动打开浏览器      （http://localhost）
   ```

3. 用演示账号登录：

   | 账号            | 密码             |
   | ------------- | -------------- |
   | `demo_admin`  | `DemoPass123!` |
   | `demo_farmer` | `DemoPass123!` |
   | `demo_system` | `DemoPass123!` |

   **登录成功 = 部署成功。**

### A4. 停止

- 停止平台：双击「停止.bat」
- 数据保存在 Docker 卷里，停止再启动数据还在，不会丢。

### A5. AI 问答功能（可选）

平台所有功能默认全可用，只有「AI 农业问答」需要填 API Key：

1. 用记事本打开解压目录里的 `iot-farm-suite\.env`。

2. 找到两行，填上（向团队负责人索取）：

   ```ini
   AI_MODEL_API_KEY=sk-你的硅基流动key
   BOCHA_API_KEY=sk-你的博查key
   ```

3. 保存后，双击「停止.bat」再双击「启动.bat」即可。

> 不填也不影响其他功能，AI 问答会提示"服务不可用"，属正常现象。

## 五、模拟器：给平台喂数据

平台自带的演示数据是**静态的**。想让页面上的温湿度像接了真板子一样实时动起来，用团队打包好的**传感器模拟器**——它在电脑上扮演 2 块虚拟板子（P001 / P002），数据经 MQTT 进入平台，和真板子走的是同一条链路。

### 5.1 模拟器在哪（要下载什么）

模拟器已随包交付，**不需要另外下载**：

- **方式 A**：解压「预构建镜像包」后，在
  `预构建镜像包/iot-farm-suite/device-simulator/鸿蒙模拟器/`
  里面有 2 个文件（**放在同一个文件夹**，别分开）：
  - `javafx-demo-1.0-SNAPSHOT.jar` —— 桌面模拟器（绿色版，免安装）
  - `sensors.dat` —— 已内置 6 台与平台数据库一一对应的传感器，开箱即用
- **方式 B**：把上面这 2 个文件从包（或 GitHub 仓库 `device-simulator/鸿蒙模拟器/`）复制到电脑任意文件夹，在自己电脑上运行即可。

### 5.2 运行前准备

电脑上需要装 **Java 20 及以上**（JDK 或 JRE 均可）：

```
https://adoptium.net/       （OpenJDK，免费，推荐）
```

装完在命令提示符输入 `java -version` 能输出版本号即为成功。

### 5.3 运行并连接平台

1. 进入 `鸿蒙模拟器` 文件夹，**双击 `javafx-demo-1.0-SNAPSHOT.jar`**。
   若双击没反应，在该文件夹地址栏输入 `cmd` 回车，运行：

   ```bash
   java -jar javafx-demo-1.0-SNAPSHOT.jar
   ```

2. 窗口顶部的 **MQTT 连接栏**，按你使用的方式填：
   - 方式 A（本地启动包）：IP `127.0.0.1`，端口 `1883`，账号 / 密码**留空**
   - 方式 B（在线环境）：IP `8.137.105.88`，端口 `1883`，账号 / 密码**留空**
3. 点 **连接**，底部日志出现"连接成功"。
4. 中间的卡片区已排好 6 台传感器，全部默认"运行"、每 5 秒上报一次。**不需要任何配置**，连接成功即开始给平台喂数据。

### 5.4 数据怎么进入平台

每台传感器每 5 秒向 `sensor/{deviceId}/data` 发一条 JSON 遥测（数值自动 ±10% 浮动）。例如 P001-TEMP 发出的消息：

```json
{"temperature":25,"deviceId":"3b8dcefd-3a51-4adc-b452-47c184c0951d","timestamp":1725000000000,"msgId":"1725000000000"}
```

平台后端订阅 `sensor/+/data`，按 `deviceId` 找到对应设备与地块写入数据库；同一地块的温湿度 30 秒内自动配对成一条 `plot_report`。页面上的温湿度曲线、灌溉推荐随之实时刷新。

> 断开模拟器后，对应设备会在平台上自动标记为"离线"，重新连接即恢复。

### 5.5 内置 6 台传感器（与平台数据库一一对应）

| 传感器        | 对应地块          | 上报指标 / 作用            |
| ----------- | ------------- | --------------------- |
| P001-TEMP  | P001（朱衣一号果园）  | `temperature` 空气温度      |
| P001-MOIST | P001（朱衣一号果园）  | `plot_moisture` 土壤湿度    |
| P001-IRRIG | P001（朱衣一号果园）  | 灌溉执行器（接收开关指令，不上报数据） |
| P002-TEMP  | P002（朱衣二号果园）  | `temperature` 空气温度      |
| P002-MOIST | P002（朱衣二号果园）  | `plot_moisture` 土壤湿度    |
| P002-IRRIG | P002（朱衣二号果园）  | 灌溉执行器（接收开关指令，不上报数据） |

### 5.6 怎么验证生效

登录平台（方式 A 打开 `http://localhost`，方式 B 打开 `http://8.137.105.88`）：

- 用 **demo_farmer** 登录 → 进入 **「我的果园」**，看到"朱衣一号 / 朱衣二号"果园的温湿度数值在不断变化；
- 或用 **demo_admin** 登录 → 进入 **「设备状态」**，看到 P001 / P002 设备状态为"在线"。

出现以上效果，即代表模拟器数据已成功进入平台。

## 六、常见问题

### Q1 双击「启动.bat」报"Docker 未就绪"

→ 没装 Docker Desktop，或装完没打开。按 A2 做。

### Q2 报"端口被占用" / `bind: address already in use`

→ 已有程序占用了 80（网页）或 1883（MQTT）。常见是 IIS、Nginx、Apache 或旧 EMQX。
处理：

```bash
netstat -ano | findstr ":80"      # 查看占用 80 端口的进程 PID
tasklist | findstr <PID>          # 看是哪个程序，任务管理器结束它
```

结束占用进程后，重新双击「启动.bat」。

### Q3 浏览器打开了但提示连不上

→ 平台还在初始化（首次启动数据库要建演示数据，约 1 分钟），等一会儿手动刷新 `http://localhost`。

### Q4 模拟器点连接失败

→ 先确认填的 IP / 端口是否正确（方式 A 是 `127.0.0.1:1883`，方式 B 是 `8.137.105.88:1883`），账号 / 密码留空；再确认平台（Docker 容器 / 在线环境）已启动。底部日志区会显示具体错误信息。
