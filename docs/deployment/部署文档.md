# 智慧农业平台 · 部署文档

> 版本：全栈基线版（feature/frontend1 + deploy/fullstack）
> 本文档写给**没接触过本项目代码的人**，三种交付方式选一种，按步骤即可完成。
> 评分标准：老师能按本文档把平台跑起来。

---

## 一、三种交付方式（怎么选）

| 方式 | 难度 | 干什么 | 适合 |
|---|---|---|---|
| **A · Windows 一键启动包**（推荐） | ★☆☆ 双击即用 | 老师下载包，双击「启动.bat」，浏览器自动打开 | 在自己电脑上演示/评审 |
| **B · 云服务器部署** | ★★★ 按文档敲命令 | 上传包到服务器，几条命令启动，长期在线 | 需要板子远程上报、多人访问 |
| **C · 云演示环境**（已就绪） | ☆☆☆ 打开即用 | 浏览器直接访问团队已部署的环境 | 临时看一眼效果 |

> 正常情况下选 **A** 就够了（推荐评审用 A + C 组合：A 证明"能部署"，C 证明"已上线"）。
> 只有电脑装不上 Docker Desktop（如虚拟机里、虚拟化被禁用）时才需要 B。

## 二、系统长什么样（一图看懂）

```
                    ┌─────────────────────────────── 服务器/电脑 ───────────────────────────────┐
  浏览器             │                                                                             │
  用户访问 ────────► │  前端 Nginx :80        ──/api──►  后端 FastAPI :8080                       │
  (老师/用户)         │   (Vue 构建产物)                    │  ▲            │                     │
                     │                                      ▼  │            │  AI_SERVICE_URL     │
                     │                             MySQL 8.0 (3306)         ▼                     │
                     │                             EMQX MQTT :1883  ◄─   AI 服务 RAG :8001        │
                     └───────────────────────────────▲─────────│─────────────────────────────────┘
                                                     │         │
                                             真板子 BearPi (现场)    调 DeepSeek API (云端/外网)
                                             = P001 地块数据
```

| 服务 | 端口 | 对外？ | 作用 |
|---|---|---|---|
| 前端 Nginx | 80 | ✅ 浏览器访问 | 网页 |
| 后端 FastAPI | 8080 | ❌ 仅容器内 | 业务/鉴权/MQTT/转发AI |
| AI 服务 | 8001 | ❌ 仅容器内 | 农业知识问答（RAG） |
| MySQL | 3306 | ❌ 仅容器内 | 数据存储 |
| EMQX | 1883 | ✅ 板子连接 | MQTT 消息中转 |

> 平台自带演示数据（数据库预置的），不插板子也能登录看到完整页面。
> 板子接上后，实时温湿度数据会覆盖演示数据。二者不冲突。

## 三、方式 A：Windows 一键启动（推荐）

### A1. 环境要求

- Windows 10 / 11（64 位）
- 已安装 **Docker Desktop**（怎么装见 A2）

### A2. 第一次准备（只做一次，约 10 分钟）

1. 下载并安装 Docker Desktop：
   ```
   https://www.docker.com/products/docker-desktop/
   ```
   一路下一步安装。装完双击打开 Docker Desktop，等右下角图标变绿、显示
   **"Engine running"**。首次启动会提示接受协议，点同意。
   > 若安装时报"虚拟化未启用"，先到 BIOS 打开 Intel VT-x/AMD-V（或用方式 B）。

### A3. 解压并启动（每次演示就这两步）

1. 把「预构建镜像包」解压到一个目录（路径不要带中文时最稳，比如 `D:\farm`）。
2. **双击「启动.bat」**，等它自动完成 5 件事：

   ```
   ① 检查 Docker        （没装/没开会在窗口里提示，按提示装好再试）
   ② 生成配置文件        （首次自动生成，登录密钥已自动随机生成）
   ③ 加载平台镜像        （首次约 3~5 分钟，之后跳过）
   ④ 启动全部服务        （MySQL / EMQX / 后端 / AI / 网页）
   ⑤ 自动打开浏览器      （http://localhost）
   ```

3. 用演示账号登录：

   | 账号 | 密码 |
   |---|---|
   | `demo_admin` | `DemoPass123!` |
   | `demo_farmer` | `DemoPass123!` |
   | `demo_system` | `DemoPass123!` |

   **登录成功 = 部署成功。**

### A4. 停止 / 数据

- 停止平台：双击「停止.bat」
- 数据保存在 Docker 卷里，停止再启动数据还在，不会丢。

### A5. AI 问答功能（可选）

平台所有功能默认全可用，只有「AI 农业问答」需要填 API Key：

1. 用记事本打开 `iot-farm-suite\.env`
2. 找到两行，填上（向团队负责人索取）：
   ```ini
   AI_MODEL_API_KEY=sk-你的硅基流动key
   BOCHA_API_KEY=sk-你的博查key
   ```
3. 保存后，双击「停止.bat」再双击「启动.bat」即可。

不填也不影响其他功能，AI 问答会提示"服务不可用"，属正常。

## 四、方式 B：云服务器部署

> 适用：电脑装不了 Docker Desktop、或需要板子远程连接、多人同时访问。
> 云服务器以阿里云 Ubuntu 22.04 为例（2核4G 及以上）。

### B1. 准备服务器与安全组

| 项 | 要求 |
|---|---|
| 云服务器 | Linux（Ubuntu 22.04 / CentOS 7+），**2核4G 及以上** |
| 安全组放行 | **80**（网页）、**1883**（板子 MQTT） |
| 演示现场 | 能上网（板子连云端 EMQX 用） |

> ⚠️ AI 问答走 **DeepSeek API**（硅基流动），不需要服务器装大模型，2核4G 足够。

### B2. 上传并解压部署包

在服务器上（或本地传到服务器后）：

```bash
# 上传「预构建镜像包」到服务器（可用阿里云 Workbench 网页终端上传，或 scp）
scp farm-prebuild.tar.gz root@<服务器IP>:/root/

# 解压（包内直接是 images/ + iot-farm-suite/ + 启动.bat ...，无中文顶层目录）
cd /root
tar -zxf farm-prebuild.tar.gz
```

### B3. 安装 Docker（若服务器还没有）

**Ubuntu：**
```bash
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-linux-x86_64" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose
```

验证：
```bash
docker --version
docker compose version    # 或 docker-compose --version
```

### B4. 配置密钥

```bash
cd iot-farm-suite
cp .env.example .env
vi .env     # 填入 AI_MODEL_API_KEY / BOCHA_API_KEY / JWT_SECRET（可从负责人处拿）
```

### B5. 加载镜像并启动

```bash
# 加载 5 个镜像（不联网）
for f in ../images/*.tar.gz; do docker load -i "$f"; done

# 启动全套
cd infra
docker compose --env-file ../.env up -d
```

> ⚠️ `.env` 在**仓库根目录**，compose 在 `infra/` 下运行，所以每条 compose 命令
> **必须带 `--env-file ../.env`**，否则后端会报 `JWT_SECRET must be configured`。
> mysql 首次启动会自动建库建表并填充演示数据，约需 1 分钟。

### B6. 验证部署成功

```bash
docker compose --env-file ../.env ps
```
期望看到 5 个服务全部 `Up`：`emqx`、`farm-mysql`、`smart-farm-backend`、`smart-farm-ai`、`smart-farm-web`。

浏览器打开 `http://<服务器公网IP>`，用 A3 的演示账号登录即成功。

### B7. 接入真板子（现场演示用）

```
MQTT 服务器：<服务器公网IP>
端口：1883
匿名连接（无需账号密码）
```
板子通电 + 连 WiFi 后自动上报 P001 地块数据，刷新页面即可看到温湿度跳动。

## 七、常见问题（遇到再查）

### Q1 双击「启动.bat」报"Docker 未就绪"
→ 没装 Docker Desktop，或装完没打开。按 A2 做；或改用方式 B。

### Q2 报"端口被占用" / `bind: address already in use`
→ 已有程序占用了 80（网页）或 1883（MQTT）。常见是 IIS、Nginx、Apache 或旧 EMQX。
处理：
```bash
netstat -ano | findstr ":80"      # Windows 查看占用进程 PID
tasklist | findstr <PID>          # 看是哪个程序，任务管理器结束它
```
服务器上则是：
```bash
docker ps -a                      # 看是否有旧容器占端口
docker rm -f <旧容器名>           # 删除旧的
docker compose --env-file ../.env up -d
```

### Q3 浏览器打开了但提示连不上
→ 平台还在初始化（首次启动数据库要建演示数据，约 1 分钟），等一会儿手动刷新 `http://localhost`。

### Q4 登录后页面数据是空的
**方式 B 场景**：真板子没在发数据（未通电 / 未连 WiFi / 没连上 MQTT）。本项目数据**全部来自现场真板子**（BearPi 上传 P001 地块数据），不依赖任何模拟器；板子不在场时实时数据为空属正常，不影响部署成功与否。方式 A 场景：内置演示数据，登录即可见完整页面。

### Q5 AI 问答报"服务不可用"
```bash
docker compose --env-file ../.env logs ai-service
```
- 日志有 **401/403**：`AI_MODEL_API_KEY` 填错或已失效
- 日志有 **timeout**：`AI_MODEL_BASE_URL` 网络不通（需能访问外网）
- 日志有 **Web search failed**：`BOCHA_API_KEY` 填错（可留空，不影响基础问答）
- 若本机是 Docker Desktop 且改了代理设置：见 Q6

### Q6 AI 服务状态显示不可用，但容器都是 Up
多半是**容器内带了无效的代理环境变量**（Docker Desktop 全局代理会把 `HTTP_PROXY=http://127.0.0.1:7890` 注入进每个容器，而容器内的 127.0.0.1 指向容器自己，代理不存在）。检查：
```bash
docker exec smart-farm-backend env | grep -i proxy
```
`infra/docker-compose.yml` 里 backend 和 ai-service 已写好清除代理的配置（`NO_PROXY: "*"` 等）。确保 compose 文件是最新的，然后重建：
```bash
docker compose --env-file ../.env up -d --force-recreate backend ai-service
```
云端 Linux 服务器无 Docker Desktop，不会遇到这个问题。

### Q7 如何看日志 / 停服务 / 重启
```bash
docker compose --env-file ../.env logs -f backend     # 实时日志
docker compose --env-file ../.env down                # 停止全部
docker compose --env-file ../.env up -d               # 再次启动
```

## 八、团队迭代（评审后）

部署完成后，团队改代码只需：

```bash
cd iot-farm-suite
git pull
cd infra
docker compose --env-file ../.env up -d --build      # 重新构建并启动
```

如需 git push 即云端自动更新，可配 GitHub Actions 流水线（见《CI-CD 自动同步说明.md》）。
