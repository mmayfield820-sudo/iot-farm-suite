# 智慧农业平台 · 部署文档

> 版本：全栈基线版（feature/frontend1 + deploy/fullstack）
> 目标：把整套平台部署到云服务器，任何人浏览器访问即用。
> 本文档写给**没接触过本项目代码的人**，按顺序执行即可部署成功。

---

## 0. 一图看懂要部署什么

```
                    ┌─────────────────────────────── 云服务器 ───────────────────────────────┐
  浏览器             │                                                                         │
  用户访问 ────────► │  前端 Nginx :80        ──/api──►  后端 FastAPI :8080                     │
  (老师/用户)         │   (Vue 构建产物)                    │  ▲            │                   │
                    │                                      ▼  │            │  AI_SERVICE_URL   │
                    │                             MySQL 8.0 (3306)         ▼                   │
                    │                             EMQX MQTT :1883  ◄─   AI 服务 RAG :8001      │
                    └───────────────────────────────▲─────────│───────────────────────────────┘
                                                    │         │
                                            真板子 BearPi (现场)   调 DeepSeek API (云端/外网)
                                            = P001 地块数据
```

| 服务 | 端口 | 对外？ | 作用 |
|---|---|---|---|
| 前端 Nginx | 80 | ✅ 浏览器访问 | 网页 |
| 后端 FastAPI | 8080 | ❌ 仅容器内 | 业务/鉴权/MQTT/转发AI |
| AI 服务 | 8001 | ❌ 仅容器内 | 农业知识问答 |
| MySQL | 3306 | ❌ 仅本机 | 数据存储 |
| EMQX | 1883 | ✅ 板子连接 | MQTT 消息中转 |

## 1. 环境要求（先确认）

| 项 | 要求 |
|---|---|
| 云服务器 | Linux（Ubuntu 22.04 / CentOS 7+ 均可），**2核4G 及以上** |
| 服务器预装 | Docker + Docker Compose（见第 3 节） |
| 安全组放行 | **80**（网页）、**1883**（MQTT 板子连接） |
| 演示现场 | 能上网（板子连云端 EMQX 用） |

> ⚠️ 本方案 AI 问答调用 **DeepSeek API**（硅基流动），**不需要**在服务器装 Ollama，2核4G 足够跑。

---

## 2. 需要准备的 2 个密钥

部署前从负责人处拿到：

| 密钥 | 用途 | 在哪拿 |
|---|---|---|
| `AI_MODEL_API_KEY` | AI 问答调 DeepSeek | 硅基流动平台（以 `sk-` 开头） |
| `BOCHA_API_KEY` | 联网搜索（天气/价格等实时问题） | 博查 open.bochaai.com（可留空=不联网） |

> `JWT_SECRET` 登录令牌加密密钥，**必填**（留空或默认值后端会拒绝启动）。任意长随机串即可，例如用 `openssl rand -hex 32` 生成。

## 3. 部署步骤

### 第 1 步：准备代码

```bash
# 在服务器上（或本地打好镜像再传）
git clone https://github.com/mmayfield820-sudo/iot-farm-suite.git
cd iot-farm-suite
git checkout deploy/fullstack   # 部署专用分支（含完整代码 + Docker 配置）
```

### 第 2 步：配置环境变量

```bash
# 复制模板为 .env（.env 不进 Git，只存在于服务器本地）
cp .env.example .env
```

编辑 `.env`，填入真实密钥：

```ini
# 必须改这两项（从负责人处拿）
AI_MODEL_API_KEY=sk-你的硅基流动key
BOCHA_API_KEY=sk-你的博查key

# 建议改（登录令牌加密，任填长串）
JWT_SECRET=改成一段随机的长字符串
```

其余保持默认即可。

### 第 3 步：安装 Docker（若服务器还没有）

**Ubuntu：**
```bash
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-linux-x86_64" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose
```

**CentOS：** 同样用 `curl -fsSL https://get.docker.com | sh`，Docker 官方脚本自动适配。

验证：
```bash
docker --version
docker compose version    # 或 docker-compose --version
```

### 第 4 步：构建并启动全套（一条命令）

```bash
cd iot-farm-suite/infra
docker compose --env-file ../.env build
docker compose --env-file ../.env up -d
```

> ⚠️ **重要**：`.env` 文件在**仓库根目录**（`iot-farm-suite/.env`），但 docker compose 在 `infra/` 目录下运行。
> 所以每条 compose 命令都**必须带 `--env-file ../.env`**，否则后端启动会报 `JWT_SECRET must be configured`。
>
> 首次会拉取镜像 + 构建，需 5~15 分钟。`mysql` 容器首次启动会自动建库建表并填充演示数据。

### 第 5 步：验证部署成功

```bash
# 查看所有容器是否都在运行
docker compose --env-file ../.env ps
```
期望看到 **5 个服务全部 `Up`**：`emqx`、`farm-mysql`、`smart-farm-backend`、`smart-farm-ai`、`smart-farm-web`。

然后浏览器打开：

```
http://<服务器公网IP>
```

应看到登录页。用演示账号登录：

| 账号 | 密码 |
|---|---|
| `demo_admin` | `DemoPass123!` |
| `demo_farmer` | `DemoPass123!` |
| `demo_system` | `DemoPass123!` |

**登录成功 = 部署成功。**

### 第 6 步：连入真板子（现场演示用）

板子固件已配置连接云端 EMQX：

```
MQTT 服务器：<服务器公网IP>
端口：1883
匿名连接（无需账号密码）
```

板子通电 + 连 WiFi 后自动上报 P001 数据。浏览器刷新页面即可看到温湿度跳动。

## 4. 常见问题（老师部署遇到问题时查这里）

### Q1: `docker compose --env-file ../.env up` 报端口被占用
```
Error: driver failed programming external connectivity ... bind: address already in use
```
**原因**：服务器上已有旧容器占用了 80/1883 端口（例如之前手动跑过一个 EMQX）。
**解决**：
```bash
docker ps -a              # 看哪些容器占端口
docker stop <旧容器名>    # 停掉旧的
docker rm <旧容器名>      # 删除
docker compose --env-file ../.env up -d      # 重新启动
```

### Q2: 容器起来了但网页打不开
```bash
# 1. 看容器是否都在运行
docker compose --env-file ../.env ps

# 2. 看后端日志有没有报错
docker compose --env-file ../.env logs backend

# 3. 确认安全组/防火墙放行了 80 端口
#    阿里云：安全组规则 → 入方向 → 添加 80/1883 端口
```

### Q3: 登录后页面数据是空的
**原因**：真板子没在发数据（板子未通电 / 未连 WiFi / 没连上 MQTT）。
**解决**：
```bash
# 看 EMQX 有没有设备连接
docker compose --env-file ../.env logs emqx
```
板子串口应显示 `MQTT connected`，浏览器刷新后数据跳动。本项目数据全部来自现场真板子（BearPi 上传 P001 地块数据），**不依赖任何模拟器**；板子不在场时页面数据为空属正常现象，不影响部署成功与否。

### Q4: AI 问答报"服务不可用"
```bash
docker compose --env-file ../.env logs ai-service
```
- 若日志有 **401/403**：`AI_MODEL_API_KEY` 填错或已失效。
- 若日志有 **timeout**：`AI_MODEL_BASE_URL` 网络不通（硅基流动需服务器能访问外网）。
- 若日志有 **Web search failed**：`BOCHA_API_KEY` 填错（可留空关闭联网，不影响基础问答）。

### Q5: AI 问答的"服务状态"显示不可用，但容器都是 Up
```bash
docker compose --env-file ../.env logs ai-service
```
若 ai-service 自身 `/health` 返回正常，但前端/后端仍显示不可用，多半是**容器内带了无效的代理环境变量**（常见于 Windows Docker Desktop 全局代理设置，把 `HTTP_PROXY=http://127.0.0.1:7890` 注入进每个容器，而容器内的 127.0.0.1 指向容器自己，代理根本不存在）。
检查：
```bash
docker exec smart-farm-backend env | grep -i proxy
```
若看到 `HTTP_PROXY=http://127.0.0.1:7890` 而 `NO_PROXY` 里没有 `ai-service`，容器间的调用会走代理而失败。
**解决**：`infra/docker-compose.yml` 里 backend 和 ai-service 已写好清除代理的配置（`NO_PROXY: "*"` 等）。确保你的 compose 文件是最新的，然后重建：
```bash
docker compose --env-file ../.env up -d --force-recreate backend ai-service
```
云端 Linux 服务器正常不会有这个问题（无 Docker Desktop 代理），可跳过。

### Q6: 如何看日志 / 停服务 / 重启
```bash
docker compose --env-file ../.env logs -f backend     # 实时看后端日志
docker compose --env-file ../.env down                 # 停止全部
docker compose --env-file ../.env up -d                # 再次启动
docker compose --env-file ../.env up -d --build        # 改代码后重新构建并启动
```

## 5. 后续更新（团队迭代不用重装）

部署完成后，团队改代码只需：

```bash
cd iot-farm-suite
git pull                          # 拉最新代码
cd infra
docker compose --env-file ../.env up -d --build      # 重新构建并启动（旧的自动替换）
```

如需**自动同步**（git push 即云端更新），负责人可再配 GitHub Actions 流水线（见《CI-CD 自动同步说明.md》）。
