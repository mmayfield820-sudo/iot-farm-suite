# Backend 目录与文件说明

## 1. 目录定位

`backend/` 是 Python 后端应用目录，负责 REST API、业务规则、数据库访问、MQTT 接入和
WebSocket 推送。SQL Workbench 是数据库管理工具，不是 Python 后端的一部分；它用于连接和
操作 MySQL 实例，后端则通过 SQLAlchemy 和 PyMySQL 访问同一个实例。

当前只初始化数据库连接核心文件，Web 框架和业务模块等后续再添加。

## 3. 数据库连接层

### `src/config/settings.py`

从项目根目录 `.env` 加载 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD` 和 `DB_NAME`。
它只负责配置，不创建数据库连接，也不执行 SQL。

### `src/database/connection.py`

使用 SQLAlchemy 创建 MySQL Engine，并通过 PyMySQL 作为驱动。连接层提供：

- `get_database_settings()`：取得缓存后的数据库配置；
- `get_engine()`：取得缓存后的 SQLAlchemy Engine；
- `get_session_factory()`：取得 Session 工厂；
- `check_database_connection()`：执行轻量连接检查。

连接层不负责建库、建表或插入 seed 数据。建库和初始化仍由以下文件负责：

- `database/schema/smart_agriculture.sql`
- `database/seed/seed_all.sql`

### `src/database/models/`

存放与数据库表对应的模型，例如 `User`、`Farm`、`Plot` 和 `Device`。只有确认 ORM
映射方案和字段设计后再添加，避免模型与 schema 不一致。

### `src/database/repositories/`

封装查询、写入和事务所需的数据访问逻辑。业务 Service 不应在路由中直接创建连接，
也不应在多个模块中散落原生 SQL。

## 4. 配置和 SQL Workbench

SQL Workbench 使用的连接信息必须与 `.env` 对应：

| 配置项 | 含义 |
|---|---|
| `DB_HOST` | MySQL 主机地址 |
| `DB_PORT` | MySQL 端口，通常为 `3306` |
| `DB_USER` | MySQL 用户名 |
| `DB_PASSWORD` | MySQL 密码 |
| `DB_NAME` | 数据库名，当前为 `smart_agriculture` |

后端不会自动创建数据库，因此首次初始化仍需在 SQL Workbench 中执行 schema；seed 是否
执行也由开发人员明确控制。

## 5. 后续扩展顺序

1. 在 SQL Workbench 确认数据库可以正常连接。
2. 填写 `.env`，运行连接检查或测试。
3. 添加 SQLAlchemy ORM 模型。
4. 添加 Repository 和 Service。
5. 确定 Web 框架后添加 API 路由和应用启动配置。
6. 增加测试数据库、迁移方案和 Docker 配置。

## 6. 安全约定

- 真实密码只放在本地 `.env`，不提交 Git。
- `.env.example` 只保留示例值。
- 生产环境应使用专用数据库账号，不使用 root。
- 数据库连接和 Session 由连接层统一管理。
