# 数据字典

## 编号

| 字段 | 规则 | 示例 |
|---|---|---|
| 用户 ID | `U` 加序号 | `U001` |
| 员工工号 | 系统管理员导入或创建，平台全局唯一；新账号的登录名 | `E2026001` |
| 身份证号 | 导入或创建时提供；仅保存 HMAC 摘要和脱敏展示值，不保存明文 | `500236********1234` |
| 农场 ID | `F` 加序号 | `F001` |
| 地块 ID | `P` 加序号 | `P001` |
| 地块编号 | 系统管理员维护，平台全局唯一 | `FJ-001` |
| 数据库设备 ID | `D` 加序号 | `D001` |
| 设备业务编号 | 地块 ID 加设备类型后缀 | `P001-TEMP` |
| MQTT 通信标识 | UUID，对应 `device.device_uuid` | `3b8dcefd-3a51-4adc-b452-47c184c0951d` |

## 设备类型

| 值 | 含义 | 单位 |
|---|---|---|
| `temperature` | 温度传感器 | 摄氏度 `C` |
| `humidity` | 土壤湿度传感器 | 百分比 `%` |
| `irrigation` | 灌溉设备 | 无 |

## 状态值

- 设备状态：`online`、`offline`
- 控制指令状态：`pending`、`success`、`failed`、`timeout`
- 告警状态：`active`、`acknowledged`、`recovered`
- 计划调整提醒状态：`active`、`handled`、`recovered`；处置方式：`adjust_as_suggested`、`keep_original_plan`、`handled`
- 用户角色：`farmer`、`farm_admin`、`system_admin`
- 账号状态：`pending_activation`、`active`、`disabled`
- 橙园和地块状态：`active`、`inactive`
- 员工导入作业状态：`validating`、`ready`、`committed`、`failed`

## 授权范围

- 农户可负责一个或多个地块，但每个地块在同一时刻仅有一名农户负责人。
- 农场管理员可管理一个或多个橙园；同一橙园可配置多名农场管理员。
- 系统管理员拥有全平台范围，不需要配置橙园或地块授权。
- 账号、橙园、地块、角色与授权范围均由系统管理员预置和维护；员工不能通过公开注册创建账号。

## 首次登录

- 新账号固定使用工号作为登录名，初始密码为身份证号后六位。
- 身份证号明文只在导入或创建请求中使用。数据库保存 HMAC 摘要以保证唯一性，API 仅返回脱敏值。
- 首次验证初始密码后只会获得一次短时的资料设置令牌，不能访问业务接口；设置不同的正式密码后账号才转为 `active`。
- 管理员重置初始密码时，账号回到 `pending_activation`，员工需再次完成首次登录。

## 时间约定

- 数据库统一保存 UTC。MySQL `DATETIME` 没有时区元数据，但本项目约定其中的值均为 UTC。
- MQTT 的 `ts`、`timestamp` 是 Unix 毫秒时间戳，按 UTC 解析。
- API 返回的时间统一使用带 `Z` 的 ISO 8601 UTC 格式，例如 `2026-08-25T06:04:21Z`；不能返回没有时区标识的时间字符串。
- 前端拿到 API 时间后，按 `Asia/Shanghai` 转换后展示给用户，不修改 API 原始值。
- 遥测消息中的采集时间与后端收到消息的时间是两个概念，数据库分别按对应字段保存。
